# 獸醫藥理學筆記頁面撰寫

這個 skill 把「幫我整理一份藥理學講義到網頁上」這句話，拆解成一套固定但不僵化的流程。它記錄的是這個 repo（`DVM-note/大三/獸醫藥理學/`）已經走過很多輪之後穩定下來的做法，主要是為了不要每次重新發明同一件事——不要每次都重新決定頁面架構長什麼樣、不要每次都手寫一次幾乎一樣的結構檢查腳本、不要因為漏了某一步（通常是藥品索引沒更新、或教科書引用其實沒真的讀過）讓使用者發現後要求返工。

## 這個 skill 假設你已經知道的事

- 整個網頁筆記站台的資料夾結構、頁面樣式規則（`.section`／`.card`／`.alert`／`.table-wrap` 這些 class 的意義），這些定義在 repo 根目錄的 `CLAUDE.md`，會自動載入，不用在這裡重複。
- `DVM-note/大三/獸醫藥理學/` 底下已經有十幾份主題頁可以參考現有寫法，不確定某個元件怎麼寫，直接看鄰近頁面的原始碼比看這份 skill 更準。

## 核心原則（貫穿整個流程）

**內容必須以講義為主，架構要跟著講義走，不是跟著自己的分類直覺走。** 這條規則的起源是使用者發現某一頁的內容其實是憑訓練資料裡的一般藥理學知識寫的，而不是真的讀過對應的課程講義；後來也發現有頁面是從「已經被別人消化過一輪的完整筆記 PDF」轉寫，而不是從教授原始投影片轉寫，這樣寫出來的章節順序、強調重點、甚至舉例都是別人的二次詮釋，不是這門課實際教的東西。所以：

- 一定要先找到、讀過**這門課實際使用的原始講義 PDF**（投影片檔名通常長得像 `A6 CNS narcotic.pdf`、`Antimicrobial 2 beta-lactam.pdf` 這種，在 `NTU/大三上/獸醫藥理學/` 或使用者提供的路徑下），不能只用「XX完整筆記.pdf」這種二手整理過的版本當唯一來源，即使手邊剛好有現成的也一樣。
- 頁面的章節順序，跟著投影片自己的順序走（investigate 一遍講義的目錄/大綱頁，通常投影片開頭就有），不要自己重新歸類成看起來更有邏輯的順序——除非講義本身就零散到需要重新組織，這時候要在對話裡跟使用者說一聲你打算怎麼重組，而不是默默改。
- 教科書（見下方）只用來**核對與補充**，不能取代講義成為主要內容來源。

## 整體流程

一份主題頁從零到完成，大致是這幾步。不是每次都從第 1 步開始——常見情境是頁面骨架已經存在只是內容需要重寫，或是頁面已經寫完只是漏了藥品索引更新，視實際情況跳過不需要的步驟。

### 1. 找到並讀懂原始講義

先確認講義 PDF 的路徑，用 pymupdf 抽出全文（含頁碼標記，方便之後對照原投影片頁碼討論）：

```bash
./.venv/bin/python .claude/skills/vetpharm-note-builder/scripts/extract_pdf_text.py \
  "{{講義路徑}}" /tmp/pharm_extract/raw_{{代稱}}.txt
```

用 Read 工具整份讀過（通常幾千到一萬多字元，一次讀得完）。如果腳本印出「平均每頁字元數偏低」的警告，代表這份投影片圖片/圖表比例很高，純文字抽取會漏掉大量資訊——這種情況要另外用 `DVM-note/_scripts/extract_pdf_images.py`（repo 裡已經有這支，不用重寫）把關鍵頁面轉成圖片，直接用 Read 工具看圖，不能只靠文字稿。

讀的時候留意：這份投影片實際涵蓋了大綱列出的所有主題嗎？有時候投影片開頭列的大綱比實際內容涵蓋範圍廣（例如列了 12 個主題但投影片只做完 4 個），或是反過來範圍比檔名暗示的更廣（例如「胺基配醣體」的檔案其實也涵蓋了四環黴素跟巨環內酯類）。這兩種情況都要在頁面的 meta-bar 或一個顯眼的提示框裡誠實寫出來，不要為了填滿大綱列出的主題，去憑印象生出投影片實際沒有的內容。範圍比檔名廣的情況，維持原本的檔名/URL 不變（避免打斷既有連結），只把 `<title>`／`<h1>`／page-subtitle 更新成反映實際涵蓋範圍即可。

### 2. 寫頁面

複製 `references/page-template.html` 到目標路徑，把所有 `{{...}}` 換掉。這份模板是空骨架，實際章節數量、每節內容份量，依講義實際內容決定——不要為了讓頁面看起來豐富就灌水，也不要為了省事就漏掉講義裡的內容。

幾個模板裡已經內建、但容易在手寫時漏掉的規矩：

- **第一節固定是「重點摘要」**，內部兩層 alert：綠色 `alert-success` 是「這章在讀什麼？」的白話導覽（3–6 句話講主線邏輯，下面接一排可點擊、依編號排列的卡片對應各章節——不要用 emoji 當編號，這個站台的視覺語言是數字），藍色 `alert-info` 是條列的臨床/國考重點（每條要講清楚「為什麼重要」，不是重述章節標題）。
- **表格優先**：任何「幾種藥/幾種物種/幾種術式的差異」都做成 `.table-wrap > table`，這是獸醫師讀者最容易一眼比較的格式，比条列文字有用。
- **機轉/因果鏈用 `.flow`**，不要寫成一整段敘述性文字。
- **四種提醒框**：`alert-success`（重點/正向）、`alert-info`（補充資訊）、`alert-warn`（注意/副作用）、`alert-danger`（禁忌/危險）——依內容的風險等級選對應顏色，不要每個框都用 info。
- **每個藥物只要講義／教科書有提到給藥途徑，一定要寫出來**（PO／IV／IM／SC／IV CRI／局部……），不要只寫劑量跳過途徑。這條規則的起源：曾經漏寫 Erythromycin 除了口服促腸蠕動劑量外，其實也能低劑量緩慢 IV 給藥促進上消化道排空，同一顆藥不同途徑可能對應完全不同的臨床情境與劑量，途徑是臨床決策的一部分，不是可以省略的細節。同一顆藥有多種途徑、且各自對應不同臨床用途時（例如口服慢性用 vs. 注射急性用），要分開寫清楚，不要籠統帶過。
- **練習題**：答案一定用 `<details class="quiz-reveal"><summary></summary>...</details>` 包起來，預設隱藏，不要寫成固定顯示的答案；至少放 1–2 題 `quiz-type-vignette`（臨床情境整合題，通常是一段病例描述＋(1)(2)(3) 子問題），其餘用 mcq/tf/saq 混搭。
- **每個 section 結尾都有 `<footer class="note-footer">`**，寫實際資料來源（見下一步）+ 固定的免責聲明。
- 若某個概念在別的主題頁已經講得很完整，這裡只放一行小字的跨頁連結（`<p style="font-size:.85em; color:var(--fg-faint);">※ ... 見 <a href="...">...</a>。</p>`），不要整段複製過來。

### 3. 教科書核對

詳細操作方式、兩本教科書的路徑、`grep` 的具體用法、核對到什麼程度算合理，都寫在 `references/textbook-crosscheck.md`，這步驟第一次做請先讀那份文件。

一句話版本的鐵律：**寫進頁面的任何教科書引用，都必須是這次對話裡真的 grep/read 過的原文，不能是憑印象寫的。** 還沒做這一步之前，meta-bar 跟 footer 要誠實寫「教科書交叉核對尚未完成」，不要预先寫成已完成。

### 4. 結構驗證

頁面（跟索引表，如果有改的話）改完後跑一次：

```bash
python3 .claude/skills/vetpharm-note-builder/scripts/verify_page.py \
  DVM-note/大三/獸醫藥理學/{{主題}}.html \
  --index DVM-note/大三/獸醫藥理學/藥品索引.html
```

這支腳本一次檢查三件最容易手動編輯時漏掉的事：`<div>`/`<table>`/`<ul>` 開合數是否配對、左側 TOC 的 `showSection('id')` 跟每個 `id="section-id"` 是否互相對應、藥品索引.html 裡所有指向這個頁面的錨點連結是否都真的存在。不要跳過這步就當作頁面完成——這三類錯誤肉眼掃過去很容易漏看，尤其是在編輯超過兩三百行的大檔案（例如藥品索引.html 本身）時。

有錯誤就照腳本印出的訊息修正，改完重跑，直到印出「全部通過 ✓」。

### 5. 更新藥品索引.html

詳細的表格格式、新增列 vs. 只補機轉欄兩種情境的具體步驟、常見錯誤，都寫在 `references/drug-index-format.md`。

一句話版本：**寫完主題頁不代表這個主題「做完了」，索引表裡對應這個主題的列（尤其是機轉欄）沒有補上真實內容之前，使用者打開索引表看到的還是一排「—」。** 這一步跟寫頁面本身同等重要，不是可選的收尾動作，也是這個 skill 存在的主要原因之一——過去好幾次都是頁面寫完了、卻在藥品索引這步漏掉或拖到下一次才做。

**這一步務必連同給藥途徑一起檢查**：索引表「臨床應用與原因」欄跟頁面內文一樣，只要講義/教科書有明確途徑就要寫出來，不能只寫適應症跳過途徑（同一條規則，見上方第 2 步）。

### 5.5 每個主題頁加上「本頁藥物總覽」表

除了站台總索引 `藥品索引.html`，**每一個主題頁自己也要有一張只列本頁藥物的總覽表**（放在「重點摘要」之後，section 2），讓讀者不用跳頁就能快速掃過整頁藥物的機轉/途徑/臨床應用。這張表**不是手寫的獨立內容**，而是直接從第 5 步剛更新好的 `藥品索引.html` 對應列**重新產生**——兩處資料只有一份來源，避免站台索引跟頁面索引各自維護、漸漸兜不起來。

第 5 步（更新藥品索引）做完、確認該主題所有列的機轉/途徑/臨床應用欄都是真實內容（不是「—」）之後，跑：

```bash
python3 .claude/skills/vetpharm-note-builder/scripts/add_drug_table.py \
  "{{檔名}}.html" "{{data-topics 用的主題字串，例如 強心配糖體 或 Lincosamide、其他抗生素與選藥原則}}"
```

腳本會自動：抓取 `藥品索引.html` 裡 `data-topics` 含這個主題字串的所有列、把連結改成頁面內的相對錨點（`#drug-xxx`，不是跨頁的 `檔名.html#drug-xxx`）、依每個藥物在頁面中第一次出現的位置排序（不是索引表裡的原始順序）、插入為 section 2、自動把後面所有 section-num 依序遞增、同步更新 TOC 與 `SECTION_NAMES`。**如果頁面已經有這張表、只是索引列的內容後來又改了（例如補了一個先前漏掉的途徑），要重跑時加 `--force`**，否則腳本會直接跳過。跑完照例用 `verify_page.py` 驗證一次。

這個腳本假設 `藥品索引.html` 每一列的「臨床應用與原因」欄已經把途徑寫清楚了（第 5 步的產出）——腳本本身不會替你補途徑，只是原封不動地把索引列的內容複製過來，所以順序是「先把索引表寫對，再生成頁面表」，不要反過來。

### 6. 更新 search-index.js

跨頁全站搜尋用的索引，每個 section 一筆條目，格式參考檔案裡任何一段既有條目：

```js
{
  subject: "獸醫藥理學", semester: "大三", week: null, weekTitle: "{{頁面標題}}",
  url: "大三/獸醫藥理學/{{檔名}}.html",
  section: "{{section id，不含 section- 前綴}}", sectionName: "{{中文章節名}}",
  keywords: "{{這節會被搜到的關鍵字，中英文都放}}",
  snippet: "{{一兩句話濃縮這節內容，會顯示在搜尋結果預覽}}"
}
```

如果是重寫既有頁面且章節 id 有變動，要把**舊的整段條目全部換掉**，不是在後面疊加新條目——舊條目指向不存在的 section id 會讓搜尋結果連結失效。改完用 `node -c DVM-note/search-index.js` 確認語法正確（一個逗號打錯就整個檔案炸掉，這個檔案沒有任何容錯機制）。

### 7. 更新科目首頁卡片

`DVM-note/大三/獸醫藥理學/index.html` 裡這個主題對應的 `.hero-door` 卡片：

- 全新主題：把 `.hero-door.hero-door--pending`（灰色佔位卡）換成 `<a class="hero-door hero-door--{{rust|amber|slate}}" href="...">` 的正式連結卡，內含 `hero-door__desc`（一兩句話描述涵蓋範圍）跟 `hero-door__link`。`rust`/`amber`/`slate` 三種只是卡片邊線的顏色變化，純視覺點綴沒有語意，跟旁邊卡片错開選一個順眼的就好。
- 既有主題大幅擴充範圍（例如原本只講一種藥物、後來發現同一份講義還涵蓋了選藥原則）：更新 `hero-door__title` 跟 `hero-door__desc` 反映新範圍，不用整張卡片重建。

同樣的邏輯也適用於根目錄 `DVM-note/index.html`（總覽頁）跟 `DVM-note/assets/nav-data.js`（頂列導覽的科目描述）——如果那邊的文字已經寫得夠通用（例如只寫「抗生素四類」這種不會因為單一頁面改動而過時的描述），就不用跟著動；只有在原本寫著「尚無筆記」或描述已經明顯跟實際內容對不上時才需要更新。

## Git

跟這個 repo 的所有其他工作一樣：**除非使用者明確要求，否則不要主動 commit 或 push。** 改完一輪頁面/索引/搜尋索引之後，用 `git status`／`git diff` 讓使用者看到改了什麼，由他們決定要不要進版控。
